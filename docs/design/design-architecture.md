# kraken-hub — Core App Architecture (design doc)

Scope: repo layout, module system, state model, config precedence, sync service, platform layer, boot sequences, degradation. Player engines, provider adapters, and module-specific UI are designed elsewhere; this doc defines the seams they plug into.

### Post-M4: the design audit (UX rounds 1–3)

An adversarial design audit was run against the shipped app at `0fb7c1b` and
re-run after each round of fixes (`de23204`, `eab18f0`, and this one). Its
report and the iteration log are the record of what changed; what follows is the
divergence from the §6.6 / §7 configuration-UI design described below, which the
body of this document still records as it was reasoned out.

| Topic | This doc says | Shipped reality (authoritative) |
|---|---|---|
| Config-UI routes (§7, "`#/` SetupView … `#/module/<id>` … `#/preview` … `#/diagnostics`") | Six named views, each on its own hash route | **Three surfaces plus a footer page.** `#/` is the home screen (`HomeView`), `#/library` is the shelf, `#/remote` is the phone remote, and About + Diagnostics are ONE page at `#/about`, reached by clicking the version line in the footer. `#/module/<id>`, `#/preview`, `#/sources` and `#/diag` survive only as hash redirects for bookmarks, docs and forks (`ConfigApp.HashRedirect` — a hash rewrite, never a navigation, per I1/I2). The audit's F1 was that `#/module/<id>` had **zero inbound links anywhere in the product**: it was a settings page nothing linked to. |
| Where a module's settings live (§7, `ModuleSettingsView` on a route) | A page per module | **Contextual, in the halo's place.** Tapping the module chip that is already active opens that module's options directly under the chips; the mirror cross-fades down to a live 56 px corner thumb to make the room. `ModuleSettingsView` still exists and still renders `mod.ConfigPanel`, but it is a component inside the home screen rather than a route. |
| `SetupView` (§7, `#/`) | The home screen is device detection, install buttons, the frame-rate instructions and a module picker | **Deleted as a screen.** Round 1's F7 measured it filling the entire 866×537 CAM window with the product below the fold. It is a one-line band under the halo shown only until a display has ever published anything to this origin (`displaySeen.ts`), and lives permanently under `#/about` as "Add to CAM" afterwards. |
| `PreviewView` (§6.6) | A preview route with a device picker, an FPS selector and a safe-area overlay | **Folded into the home screen.** The halo at the top of `#/` *is* the real display page in an iframe (`./?kraken=1&sim=<preset>`), booted at the panel size the display actually reported. The picker and the overlays did not survive; the simulator parameters they drove are still URL params (§4.2) and the diagnostics page still exercises them. Video is the one module without a live mirror — a second decoder on this origin is not affordable — and draws a poster plus a live position arc instead (`VideoHalo`). |
| The composition's budget | Unstated | **The page, not the panel.** CAM's Configuration Browser is 866×537, and every module's home screen must fit it whole — halo, action, chips, options strip, options panel, nav row and footer — with `document.scrollHeight <= clientHeight` and nothing scrolling inside its own box. Round 3's F2 found the round-2 assertions measuring the options PANEL and passing while the nav row was bisected by the fold. `tests/e2e/home-composition.spec.ts` measures the document for every module in every panel state; opening **Advanced** is the one state allowed to scroll, and it scrolls the page rather than a hidden box (F1). |
| Touch targets | Unstated | **44 px, for every visible interactive element, at ≤700 px.** `tests/e2e/tap-targets.spec.ts` enumerates the DOM rather than a list of selectors — the round-2 list-based test passed while the four module chips sat at 36 px (F6). |
| The app's vocabulary | Unstated | **`src/config/vocabulary.ts`**, with `src/config/vocabulary.test.ts` proving no second literal copy exists in the tree. CAM's two menu paths and the frame-rate instruction's grammar live in `src/config/camPaths.ts` on the same rule. |
| Claims about the LCD panel | Unstated | **A type, not a phrase — `src/app/config/panelClaims.ts`.** `panelPresence.ts` (round 6) derives one answer to *is a Kraken there, and is it saying anything right now?*; round 7 found that enforcing it with a two-phrase grep bought exactly one round, because the rule was satisfied per file by a single import. A claim is a `PanelClaimSpec` now — the same sentence in three tenses, one per presence state — and the only ways to render one (`panelClaimText`, `<PanelClaim>`) require a `PanelPresence`. `vocabulary.test.ts` scans every config surface's string literals and JSX text for the present-tense panel-verb family and fails on any that does not live in `vocabulary.ts` or `panelClaims.ts`, so a claim typed inline next month is a failing test rather than a screenshot in the next audit. |
| A control with no scale behind it | Unstated | **It withdraws rather than degrading.** `LOOP_MAX_SEC` is a rail length, not a duration; with nothing reported the scrubber draws the rail and nothing else — no seek input, no loop band, handles disabled — and `src/app/config/loopPoints.ts` is the one guard every write path goes through, so no gesture can persist a loop point against an invented hour. Same narrowing as the quality ring and the presence spine: **without evidence the app does less, never something plausible.** |
| `#/remote` in CAM's own window | Unstated | **Two surfaces on one route.** CAM's Configuration Browser gets PAIRING — the QR at camera size, the room, rotate and copy — because a window is not a remote control for the machine it runs on, and every part of a remote has a truer version on that window's home screen. Everything that really is remote from the Kraken keeps the instrument. `ownsBytes()` decides, so no new signal was invented (`surface.ts`). |

### Post-M4: the design audit (round 5)

Round 5's theme was **the app saying something it does not know to be true** — a
control reporting a number nobody measured, a receipt standing over a library
that had changed underneath it, a form accepting input it had already decided was
unusable. Three of its six findings are corrections to what this document
specifies.

| Topic | This doc says | Shipped reality (authoritative) |
|---|---|---|
| The shared progress meter (`src/ui`) | Unstated beyond "a usage meter" | **An unknown percentage is drawn as unknown, not as done.** `Meter` took `pct: number \| null` and rendered `null` — which is exactly what a transfer of unknown total, or an estimate the browser would not give, produces — as a **full 100 % bar**. The one state that means "we do not know" was pixel-identical to the one that means "finished". `null` is an indeterminate treatment now, and it is the shared component's problem rather than each caller's, because every caller that hands it a `null` had already got this wrong (round 5, S3). |
| Room code entry (§5.2) | `normalizeRoomCode` returns `null` for anything that is not a canonical code | **A refusal is now visible.** The pairing card called `normalizeRoomCode`, got `null`, and **returned** — no notice, no state change, a Join button that did nothing and a card that looked exactly as it had. The field filters typed characters to the Crockford alphabet (so `I`, `L`, `O` and `U` never land in it) and an unusable code renders an inline notice with `aria-invalid` on the input. A validator whose failure path is silence is a validator the user cannot see (round 5, S5). |
| The composition's budget, on the About page | Covered for the home screen (above) at 866×537 | **The 390 px floor binds every route, not just `#/`.** The Connection section's **Route** segmented control — four options, one of them the three-word "Same PC only" — overflowed its row below 390 px and forced the whole page sideways, on the one page somebody opens *because* something is already wrong. Horizontal scroll is the composition failure the home-screen assertions were written to catch, one route over (round 5, S6). |

## 0. Cross-cutting invariants (executors: violate none of these)

| # | Invariant | Enforcement |
|---|---|---|
| I1 | The Kraken Browser page never performs a top-level navigation. No `history.pushState`, no `location.href=`, no `<a href>` without `preventDefault`, no meta-refresh. `location.reload()` (same URL) is the *only* permitted exception, watchdog-gated. | ESLint `no-restricted-globals` on `location.assign/replace/href`; unit test asserts the display shell contains no `<a>` (`src/app/display/shell.dom.test.ts`); `tests/e2e/no-navigation.spec.ts` asserts `.kh-stage a` is empty in the built page. |
| I2 | `window.nzxt` is **never** assigned wholesale. Only `window.nzxt.v1.<prop> = …`. | `src/platform/nzxt.ts` is the only file allowed to touch `window.nzxt` (ESLint `no-restricted-properties` elsewhere). DEV tripwire: `Object.defineProperty(window,'nzxt',{set})` logging a stack trace. |
| I3 | No geometry constant is hardcoded outside `src/platform/geometry.ts`. `640` appears in exactly two places: the fallback in `geometry.ts` and the submission image spec. | Grep test in CI: `/\b(640|320|240)\b/` outside allowlisted files fails. |
| I4 | No shell update may originate inside a `FrameClock` tick. (Written as "no React state update" while the display had React; W9 removed the framework, not the rule — the shell's DOM writes are governed by it exactly as `setState` was.) | `FrameClock` sets a module-scope `inFrame` flag; the display shell subscribes only to the store and to geometry, never to the clock, and every periodic read it does take (the debug overlay, the layer governor) is on a 1 s `setInterval` off the frame path. |
| I5 | Every persisted key is prefixed `kraken-hub:`; IndexedDB db name is exactly `kraken-hub`. The `<user>.github.io` origin is shared with all the user's other repos. | CI grep: `localStorage.(get\|set)Item\(` outside `src/state/storage.ts` and `src/sync/transports/LocalStorageTransport.ts` fails. |
| I6 | Blobs never enter localStorage. State JSON is capped at 256 KB; sync payloads at 8 KB. | Runtime assert + throw-with-diagnostic in `commit()` / `publishState()`. |
| I7 | Vite `base: './'`. No root-relative URL (`/foo`) anywhere in src or index.html. | CI grep on built `dist/index.html` for `src="/"` / `href="/"`. |
| I8 | Display-side code must not import from `src/app/config/**` or `src/ui/**`. | ESLint `import/no-restricted-paths` zones + a bundle-graph CI check that the `display` chunk contains zero `src/ui/` modules. |

## 2. The module system

### 2.1 The display page ships without a framework (W9)

At `targetFps = 40` the frame budget is 25 ms, and CAM additionally captures and **compresses** each frame (research: achieved FPS is content-dependent). Our JS budget should be ≤ 4 ms/frame.

- The per-frame rule has never changed and is not what W9 is about: **everything per-frame is written directly to DOM/canvas by the module's imperative renderer** inside the `FrameClock` callback, because a video position readout, a clock second hand or a stats gauge at 40 Hz would otherwise create 40 reconciliations and 40 allocations/sec of props objects, plus GC pressure that shows up as jitter on a device we cannot profile. Invariant I4 enforces it.
- What changed is the SHELL around that renderer. This section used to argue for keeping React on the display path at ≈ 45 KB gz, bought with error boundaries, `React.lazy` code-splitting and a component vocabulary shared with the config app. Two of those three stopped being reasons: dynamic `import()` does the code-splitting on its own, and the display shares no components with the config app at all — invariant I8 forbids it. What was left was an error boundary, which is a `try`/`catch` around the one function that writes the shell.
- The measured price was higher than the estimate: `vendor-react` was **57.5 kB gzip of a 89.15 kB `displayCriticalPath`** — nearly two thirds of everything the hidden Kraken Browser downloads before the LCD can show a frame — to render a dozen nodes that change a handful of times per session.
- So the display shell is plain DOM: `src/app/display/DisplayApp.ts` subscribes to the same two external sources the component tree read (`runtime.store`, `runtime.geometry`) and writes the stage, the compositor root, the splash, the module error card, the low-FPS advisory and the debug overlay directly, through the ~110-line helper in `src/app/display/dom.ts` (`el`, `setText`/`setAttr`/`setClass` that write only on change, and `slot`, a fixed position holding zero or one node — which is how `{cond && <Card/>}` keeps its z-order without a diff). `src/diag/DiagOverlay.ts` went the same way.
- **Measured, same build, same gzip level: `displayCriticalPath` 89.15 → 31.94 kB gzip (−57.21 kB, −64 %), 7 → 6 JS requests, and first contentful paint on the display route 36–40 ms → 24–28 ms in a local preview.** The budget gate went from 90 to 35 kB.
- The rule is enforced on the built graph, not by convention: `scripts/check-bundle-size.mjs` walks the manifest transitively from the display entry and fails the build if any reached chunk contains `react`, `react-dom` or `scheduler` (`budgets.json` → `displayGraph.noFramework`, reported as the `displayNoFramework` row). That is the only thing that keeps 35 kB from silently becoming 90 again.
- **The configuration page is untouched.** It is a real application with forms, routing and a component library, it is never downloaded by the panel, and `vendor-react` still exists for it with its `configUi` budget unchanged. This is not a project-wide framework removal; it is the observation that the *display* was never rendering anything a framework was needed for.

Per-module rendering substrate guidance (`capabilities.substrate`, advisory):
- **video** → DOM (`<video>` / cropped `<iframe>`; canvas would force a decode→draw copy).
- **image/gif** → DOM `<img>` (animated GIF decoding is free and off-main-thread).
- **clock, stats** → `<canvas>`, redrawn in `frame()`. Draw a **static background layer once** (offscreen canvas or a second stacked canvas) and only repaint the small moving region each frame — this directly reduces changed-pixel entropy and therefore raises achieved FPS through CAM's compressor.

### 2.2 The `KrakenModule` interface (`src/modules/types.ts`)

```ts
export type ModuleId = string;                 // kebab-case, /^[a-z][a-z0-9-]{1,23}$/

export interface ModuleCapabilities {
  needsMonitoring: boolean;      // subscribe to the 1 Hz CAM feed
  needsFrameLoop: boolean;       // wants frame() ticks
  usesMedia: boolean;            // reads IndexedDB blobs
  hasTimeline: boolean;          // participates in AppState.playback (§3.2)
  motionLevel: 'static' | 'low' | 'full';   // drives the low-FPS advisory
  substrate: 'dom' | 'canvas' | 'mixed';
  audio: 'none' | 'optional';
  remoteCommands: readonly string[];         // ops this module accepts on ch='cmd'
}

export interface KrakenModule<C = unknown> {
  readonly id: ModuleId;
  readonly name: string;                     // "Video Player"
  readonly summary: string;                  // one line, shown in the module picker
  readonly icon: string;                     // inline SVG path data (no asset request)
  readonly configVersion: number;            // bumped on breaking config change
  readonly capabilities: ModuleCapabilities;

  readonly defaults: C;
  /** MUST NOT throw. Coerce, clamp, drop unknown keys, fill from defaults. */
  validate(raw: unknown): C;
  /** Optional per-module config migration. Called before validate(). */
  migrateConfig?(fromVersion: number, raw: unknown): unknown;

  /** Declarative URL-param → config patch mapping. Keys are namespaced-checked in CI. */
  readonly urlParams?: Readonly<Record<string, UrlParamSpec<C>>>;

  /** Lazy display renderer factory — the only thing the LCD bundle pulls in. */
  loadDisplay(): Promise<{ createRenderer(): DisplayRenderer<C> }>;
  /** Lazy React config panel — never reachable from the display chunk. */
  ConfigPanel: React.ComponentType<ModuleConfigProps<C>>;   // wrapped in React.lazy by registry
}

export interface UrlParamSpec<C> {
  /** dot path into the module config, e.g. 'source.raw' or 'loop.startSec' */
  path: string;
  parse(raw: string): unknown | undefined;   // undefined = invalid, param ignored + logged
  doc: string;                               // rendered into docs + DiagnosticsView
}
```

### 2.3 `DisplayRenderer` — the imperative contract

```ts
export type UpdateReason = {
  changed: string[];                 // dot paths that differ from the previous config
  origin: 'boot' | 'local' | 'remote' | 'url' | 'reinit';
};
```

### 2.7 Compositor (`src/render/LayerHost.ts`)

`ModuleHost` is gone. The display no longer mounts *a module*; it composites a
**look** — `{ layers: Layer[] }`, bottom first — and a one-layer look is the
single-module display it replaces, DOM for DOM.

- **One absolutely-positioned host `div` per ON layer** under `.kh-stage`, and
  **DOM order IS z-order**. There is no `z-index` anywhere:
  `scripts/check-invariants.mjs` fails the build on one, because a hand-written
  stacking literal is a second, invisible order the compositor and the editor
  cannot see.
- **The base host never moves.** It is created once and is always
  `root.firstChild`; overlays are inserted after it. Re-inserting an `<iframe>`
  discards its `contentWindow` and re-navigates (a YouTube embed would reload),
  while a `<canvas>` keeps its WebGL context across `insertBefore` — which is
  the same fact that makes `video` `roles: ['base'], maxInstances: 1`.
- **Reconcile by id, never by position**: a transform is one style write, a frame
  change is one `geometry()` call, a config change is `update()` and not a
  remount, and only a *kind* change on the same id remounts.
- **One frame-clock subscription** for the whole stack, fanned out in array
  order, with per-layer timings kept in closure state (invariant I4). The
  governor (`src/render/layerGovernor.ts`) moves the stack between
  `full → reduced → hz1` with ten-second/thirty-second hysteresis and
  **never hides, removes or unmounts a layer**.
- Placement rules (roles, `maxInstances`, decoder/GL caps) are not decided here:
  `normalizeLook()` in `src/modules/stack.ts` is the only site that runs them.
  Per-layer geometry is not decided here either: `src/render/layerBox.ts` is
  shared verbatim with the editor and the phone replica.
- `src/render/lookOf.ts` is the adapter between the document and the compositor,
  and it is **total** — every input, including a document with no `look` field at
  all, yields a valid base-only look.

Full specification, including the cost model and the governor's tiers:
[`docs/design/design-layers-architecture.md`](design-layers-architecture.md)
§2 (compositor), §3.4 (placement), §7 (budgets and governor).

### 3.1 Keys

| Key | Contents | Written by | Notes |
|---|---|---|---|

### 3.3 Atomic write (`src/state/storage.ts`)

```ts
export function commit(mutate: (s: AppState) => AppState, meta: { role: Role }): AppState {
  const cur = readState();                       // migrate + validate, never throws
  const next = validateAppState({ ...mutate(cur),
    schema: SCHEMA_VERSION,
    rev: Math.max(cur.rev, seenRevHighWater) + 1,
    updatedAt: Date.now(),
    writerId: CLIENT_ID,
    writerRole: meta.role,
  });
  const json = JSON.stringify(next);
  if (json.length > 256_000) throw new StateTooLargeError(json.length);
  try { localStorage.setItem(STATE_KEY, json); }
  catch (e) { degradeToMemory(e); }              // QuotaExceededError → in-memory store + UI error
  lastRawWritten = json;
  memBus.emit(next);                             // in-process: storage event does NOT fire in the writer
  return next;
}
```

One key, one `setItem`, one JSON string → readers never observe a torn state. Read path: `getItem → JSON.parse → migrate → validateAppState`; on parse failure, stash the raw string at `kraken-hub:state:corrupt` (one slot, overwritten) and return `defaults`.

### 3.4 Validation without a runtime dependency

Hand-rolled coerce/clamp validators in `src/state/validate.ts` (~250 lines) using a tiny combinator set: `str(def, allowed?)`, `num(def, min, max)`, `bool(def)`, `enum_(def, values)`, `obj(shape)`, `passthrough()`. Rationale: zod adds ~14 KB gz to the **display** chunk for a job that is 250 lines of clamping, and the display path must stay under budget. Validators never throw — invalid leaves fall back to the default and record a `ValidationNote{path, got, used}` list surfaced in DiagnosticsView.

### 3.5 Watching (display side)

```ts
export function watchState(onChange: (s: AppState, via: 'event'|'poll'|'mem') => void): () => void
```
- `window.addEventListener('storage', e => { if (e.key === STATE_KEY || e.key === null) refresh('event'); })` — `e.key === null` means `localStorage.clear()`.
- 1 s `setInterval` poll: compare the **raw string** to `lastRaw` (cheap, no parse); parse only on difference.
- In-process `memBus` for same-document writes.
- Echo suppression: skip if `next.writerId === CLIENT_ID && next.rev <= lastAppliedRev`.
- Counters `{viaEvent, viaPoll}` exposed in DiagnosticsView and telemetry — this is how the community empirically answers "is the storage event reliable in the CAM webview?".
- Also refresh on `visibilitychange→visible`, `pageshow`, and after every watchdog re-init.

### 3.6 IndexedDB (`kraken-hub`, version 1)

```
store 'media'  keyPath 'id'   index 'byCreated' on createdAt, index 'bySha' on sha256
  { id: string,               // 'med_' + 16 hex
    blob: Blob,
    kind: 'video'|'image'|'gif',
    mime: string, bytes: number, name: string,
    width?: number, height?: number, durationSec?: number,
    sha256?: string,          // for re-link after eviction
    createdAt: number, lastUsedAt: number }

store 'meta'   keyPath 'key'
  { key: 'persistGranted'|'lastGcAt'|'dbCreatedAt', value: unknown }
```

- State stores **`mediaId` only**. Blob URLs die on reload and are never persisted; `blobUrls.ts` is a ref-counted `Map<mediaId, {url, refs}>` created at `mount()` and revoked at `unmount()`.
- `navigator.storage.persist()` is requested from the **config page inside a click handler** on first upload (best chance of grant), and re-checked (`persisted()`) at display boot. Result + `estimate()` shown in DiagnosticsView.
- GC runs only on config boot, never on the display: delete `media` rows unreferenced by any `state.modules[*].cfg` **and** `lastUsedAt` older than 30 days, behind an explicit "Manage storage" list. Never delete a referenced item silently.
- Eviction recovery: if `getMedia(id)` misses, the module renders "media missing — re-upload" and the config UI offers re-link by `name + bytes + sha256`.

### 3.7 Migration (`src/state/migrations.ts`)

```ts
type Migration = (s: any) => any;
const MIGRATIONS: Record<number, Migration> = {
  // 1: (s) => ({ ...s, newField: default, schema: 2 }),
};

export function migrate(raw: any): { state: any; notes: string[] } {
  let s = raw, notes: string[] = [];
  if (typeof s?.schema !== 'number') { s = { ...DEFAULTS, ...s, schema: 1 }; notes.push('missing-schema'); }
  if (s.schema > SCHEMA_VERSION) {                 // written by a NEWER build
    localStorage.setItem(FUTURE_KEY, JSON.stringify(raw));   // preserve, do not destroy
    return { state: DEFAULTS, notes: ['future-schema'] };     // ConfigApp shows a warning banner
  }
  while (s.schema < SCHEMA_VERSION) {
    const fn = MIGRATIONS[s.schema];
    if (!fn) { notes.push(`no-migration-from-${s.schema}`); return { state: DEFAULTS, notes }; }
    s = fn(s);
  }
  return { state: s, notes };
}
```

Rules: forward-only; every migration ships with a fixture test (`__fixtures__/state-v<N>.json` → asserted output); module configs migrate independently via `configVersion` + `migrateConfig`, applied inside `validateAppState` after app-level migration. **Never** rename `kraken-hub:state:v1` — that would strand every existing user.

## 4. Config precedence

### 4.1 Layers

Resolved lowest → highest:

1. **defaults** — `src/state/defaults.ts` + each module's `defaults`.
2. **url** — params present in `location.search`.
3. **persisted** — `kraken-hub:state:v1`.
4. **remote** — in-memory patch stack from `SyncService.onState` / `onCmd` this session.

This is `defaults < url < persisted < remote` as briefed: URL params **seed** a fresh install and are shadowed once the user saves anything in the config UI (which always writes a full snapshot, so every field is "present" in the persisted layer).

> **Corrected on 2026-09-02: there is no pin flag, and a URL param always wins.**
> The `?pin=1` escape hatch designed here shipped as a parsed key that nothing
> ever read, and it has been removed from `KNOWN_KEYS`, `RuntimeFlags` and the
> URL parser. It was unnecessary from the start: the parsed URL patch is
> installed as a **non-persistent store overlay** by `src/app/display/mount.ts`,
> so every URL parameter sits on top of the resolved document and wins
> unconditionally for the life of that page load. The shipped precedence is
> `defaults < persisted < merged < url`, with the remote patch stack folded into
> the merged document beneath the overlay.
>
> This is what the escape hatch was for, so the case that motivated it is
> already covered: two Web Integration cards on one `<user>.github.io` origin
> share one localStorage, and each still gets its own configuration from plain
> URL params, with no flag to remember. The trade is the other direction — a URL
> choice is deliberately temporary and never written back to storage. **To make
> one permanent, set it in CAM**, where it persists like any other setting.



Merge semantics: deep merge, **per leaf**, later layer wins. Arrays and `source` objects replace wholesale (never element-merged). `null` is a value, not an absence. The result is `Object.freeze`d recursively in DEV.

```ts
// src/state/precedence.ts
export interface Layers { defaults: AppState; url: DeepPartial<AppState>;
                          persisted: DeepPartial<AppState>; remote: DeepPartial<AppState>; }
export function resolveState(l: Layers): AppState {
  // No pin option: the parsed URL patch is ALSO installed as a store overlay by
  // mountDisplayApp, so it wins over this result for the life of the page load.
  return validateAppState([l.defaults, l.url, l.persisted, l.remote].reduce(deepMergeLeaf));
}
```

The **remote layer is in-memory**, so a reload drops it — recovered from the MQTT retained snapshot, or (with `sync.persistRemote: true`, the default) from localStorage because the display commits remote-received state, throttled to ≥ 2 s and coalesced. Without `persistRemote`, a reload on a network-down display would revert to the CAM-configured state; that behavior is offered as an option for users who want the CAM config to be authoritative. The flag governs the DOCUMENT only: the sync clock slot (`kraken-hub:v1:sync-clock:<role>`, a self-contained `{ stamp, value }` register table, slot version 2) is written either way, because a page that persists a stamp without the value it described pairs it with whatever its document happens to hold and then out-ranks the truth room-wide.

### 4.3 Command semantics vs. state semantics

- `ch='state'` (retained) = **desired configuration**. Idempotent. Merged into the remote layer. A cold display applies exactly one of these.
- `ch='cmd'` (transient, never retained) = **imperative**, non-idempotent, must never be replayed. Examples: `seekBy(+10)`, `next`, `reload`, `identify`, `previewSeek`. `cmd` envelopes older than 15 s are dropped on receipt — this is what makes ntfy's 12 h replay safe.

### 5.1 Interfaces (`src/sync/types.ts`)

### 5.2 Room code, topic derivation, encryption (`roomCode.ts`, `crypto.ts`)

```
ALPHABET = "0123456789ABCDEFGHJKMNPQRSTVWXYZ"        // Crockford base32, no I L O U
generate(): 8 chars from crypto.getRandomValues       // 40 bits
normalize(s): uppercase, strip non-alphanumeric, I|L→1, O→0, then validate /^[0-9A-HJKMNP-TV-Z]{8}$/

topicId = crockford32( SHA-256( "kraken-hub/v1/room|" + code ).slice(0, 10) )   // 80 bits → 16 chars
key     = HKDF-SHA256( ikm = utf8(code),
                       salt = utf8("kraken-hub/v1/salt"),
                       info = utf8("aes-256-gcm/v1") ) → 32 bytes → AES-GCM CryptoKey
```

Wire frame: `base64url( 0x01 || iv[12] || ciphertext||tag )`, `iv = crypto.getRandomValues(12)` fresh per message. **AAD = `utf8(topicId + "|" + channel)`** so a ciphertext cannot be replayed onto a different channel.

Honest limitation, stated in `docs/04-remote-control.md`: 40 bits of entropy under HKDF is weak against an offline attacker who has already located the topic. Mitigations: (a) the topic is itself derived and unguessable; (b) contents are low-value (a media URL and a seek position); (c) an optional `sync.passphrase` upgrades the KDF to PBKDF2-SHA256, 600 000 iterations, salt = `topicId` — offered in RemoteView as "extra protection". Decrypt failures are counted; 10 failures within 30 s raises "no messages could be decrypted — wrong room code?" rather than failing silently.

### 5.3 Envelope (`src/sync/envelope.ts`)

```ts
interface Envelope<T> {
  v: 1;                       // protocol version, independent of AppState.schema
  ch: Channel;
  ts: number;                 // epoch ms, sender clock
  src: string;                // 12-char clientId
  role: Role;
  seq: number;                // monotonic per src, resets on reload
  rev?: number;               // ch='state' only — AppState.rev (Lamport)
  body: T;
}

interface SyncStateBody {
  activeModuleId: ModuleId;
  modules: Record<ModuleId, { v: number; cfg: unknown }>;   // full map; blobs NEVER included
  playback: PlaybackState | null;
  render: RenderSettings;
  partial?: true;             // set when the full map exceeded 8 KB and only the active module was sent
}
interface CmdBody { op: CmdOp; arg?: unknown }
type CmdOp = 'play'|'pause'|'toggle'|'seekTo'|'seekBy'|'previewSeek'|'setRate'|'setLoop'|'clearLoop'
           | 'next'|'prev'|'setModule'|'nudge'|'reinit'|'reload'|'requestState'|'identify'|'ping';
interface TeleBody {
  status: 'ok'|'loading'|'error';
  moduleId: ModuleId; engine: string | null;
  playback: PlaybackState | null;
  fps: { target: number; achieved: number; longFrames: number };
  geometry: { width:number; height:number; shape:string; source:string; dpr:number };
  storage: { via: { event:number; poll:number }; persisted: boolean };
  monitoring?: { cpuLoad?:number; gpuLoad?:number; liquidTempC?:number; stale:boolean };
  errors: string[];           // last 3, truncated to 200 chars each
  version: string; uptimeMs: number;
}
```

> **Superseded on 2026-09-02 (protocol `v: 2`).** The envelope above is the
> shape as designed; what ships adds two fields and drops the `rev` ordering.
> Where they disagree, the code wins — see `src/sync/merge.ts`.
>
> - `stamps?: Record<leafPath, [t, c, src]>` — the hybrid logical clock stamp of
>   the write that produced each value the body carries. Only leaves somebody
>   has actually written appear; a missing stamp reads as the beginning of time,
>   so it can fill a gap and can never overturn a decision.
> - `clock?: [t, c, src]` — the sender's own clock, folded into the receiver's.
> - `body.look?: Look` — the arrangement (§6.1 of the layers design).
>   `activeModuleId` is written alongside it for one release and is the SAME
>   merge unit as `look.layers[0].kind`.
>
> The merge is per-leaf last-writer-wins by that clock, which is commutative,
> associative and idempotent — so a retained replay, a keepalive republish and a
> duplicate are all no-ops on their own merits, and the `rev`-based ordering,
> the "is this a replay?" branch and the acknowledgement map that briefly
> replaced it are all gone. `AppState.rev` survives only where it was always
> correct: arbitrating two writers of ONE localStorage document.
>
> **Clock skew, honestly.** A write made after seeing another always wins,
> regardless of skew, because a stamp is `max(now, the latest stamp this page
> has seen)`. Only two writes that are concurrent *within the two devices'
> skew* are decided by whose clock reads later. Nothing is ever left split.
> `v` moved to 2 because a `v: 1` peer sends no stamps, and reading its writes
> as older than time would lose them silently — a mixed-build room refuses
> instead.

State is always a **full snapshot, never a delta** — a cold display must be correct after exactly one message. Assert serialized envelope ≤ 8 KB; if over, drop inactive modules and set `partial: true`; if still over, drop `render` detail and log.

Position over the wire: never a bare `posSec`. Always `posSec + posAtTs`; the receiver computes
`effective = paused ? posSec : posSec + clamp((Date.now() - posAtTs)/1000, 0, 30)`.
The 30 s clamp is deliberate (§7.5, C2): clock skew between a phone and a PC, and multi-hour sleeps, both make naive extrapolation produce absurd seeks.

### 5.4 Transports

**`LocalStorageTransport`** — always active, no encryption (same origin), `caps: {retained: true (state key IS the retained store), replayMs: Infinity, needsNetwork: false}`.
- `state` channel: reads/writes the canonical `kraken-hub:state:v1` via `state/storage.ts` — it *is* the store, not a parallel copy.
- `cmd` / `tele`: single-slot keys `kraken-hub:bus:cmd` / `:tele` holding `{nonce, env}`; the nonce guarantees a value change so the `storage` event always fires. Consumers dedup on `(src, seq)`.
- Backed by the same 1 s poll fallback as `watchState`, so a webview that swallows `storage` events degrades to ≤ 1 s latency instead of failing.

**`MqttTransport`** (mqtt.js 5.x, ESM):
```
url    wss://broker.emqx.io:8084/mqtt        (configurable: sync.mqttUrl)
topics kh/v1/<topicId>/{state,cmd,tele}
connect { clientId: 'kh_'+rand12, clean: true, keepalive: 30, protocolVersion: 4,
          connectTimeout: 8000, reconnectPeriod: 0,      // we own backoff, not mqtt.js
          will: role !== 'config' ? { topic: `.../tele`, payload: seal({type:'offline'}),
                                      qos: 0, retain: false } : undefined }
```
- `connect()` resolves only after **CONNACK and SUBACK** (research caveat: publishing immediately after CONNECT and closing fast silently loses retained messages).
- `publish(state, {retain:true, qos:0})` awaits the publish callback. **No will on `state`** — a will would wipe the snapshot a reloading display depends on.
- `close()` calls `end(false, cb)` and awaits, with a 1.5 s flush ceiling.
- **Retained keepalive**: every 5 min, re-publish the current retained snapshot — but only if `state.writerId === self` (the last writer owns republish), preventing two peers from duelling.
- Reconnect backoff (`src/sync/backoff.ts`): `1s, 2s, 4s, 8s, 15s, 30s, 60s` cap, ±20 % jitter, counter reset after 30 s of stable connection.

**`NtfyTransport`**:
```
publish   POST https://ntfy.sh/kh-v1-<topicId>   body = base64url frame, Content-Type: text/plain
                (no custom headers → simple request → no CORS preflight)
subscribe new EventSource('https://ntfy.sh/kh-v1-<topicId>/sse')
recovery  GET  https://ntfy.sh/kh-v1-<topicId>/json?poll=1&since=10m
```
- One flat topic (ntfy has no hierarchy); `ch` inside the envelope discriminates. `caps.retained = false`, `replayMs = 600_000`.
- Retention emulated: the state owner republishes every **4 min** (safely inside the 10 min recovery window) plus immediately on any `cmd:requestState`.
- Recovery: poll `since=10m`, take the **last** envelope with `ch==='state'`, then open the EventSource. `since=10m` not `since=all` — replay is capped at 10 MB/topic (`X-Messages-Truncated: 1`).
- Publish throttle ≤ 2/s (public rate limits undocumented). On HTTP 429: exponential backoff, coalesce pending state, drop non-critical `cmd`s, and enter "state-only every 4 min" mode with a visible notice on the remote.
- Own liveness watchdog: if no SSE message or keepalive for 90 s, tear down and recreate the EventSource.

### 5.5 Orchestration: failover, dedup, roles

**Slot model.** `LocalStorageTransport` always runs (it is free and covers the CAM config↔display case with a completely independent failure domain). One **network slot** holds at most one of `mqtt | ntfy`.

Failover ladder:
1. `transport: 'auto'` → try `mqtt`. Connect timeout 8 s.
2. Failure, or 3 consecutive reconnect failures within 60 s → switch the network slot to `ntfy`; `SyncStatus.network = 'degraded'`; remote UI shows "fallback transport — higher latency".
3. Background re-probe of `mqtt` every 5 min. On success, subscribe on both for a **10 s handover window** (dedup handles overlap), then close ntfy and re-publish the retained snapshot.
4. Both down → `network: 'offline'`. The display keeps running on localStorage + persisted state; the remote page shows "offline — use the CAM configuration browser."

Dedup / ordering (in `SyncService`, transport-independent):
- LRU `Set<`${src}:${seq}`>` size 256 → drop duplicates (handover window, ntfy replay, MQTT retained redelivery).
- Drop any envelope with `src === self.clientId`.
- Drop `ch='cmd'` with `Date.now() - ts > 15_000` — makes replay-based transports safe.
- Accept `ch='state'` only if `rev > lastAppliedRev`; update `seenRevHighWater = max(...)` so the next local `commit()` produces a strictly greater `rev` (Lamport).
- Conflict resolution is deliberately last-writer-wins on the whole document, not CRDT: the state is small, human-driven, and rarely concurrently edited. Ties on `rev` break on `(ts, src)` lexicographic.

**Role matrix — exactly one publisher per direction per channel** (this is what prevents feedback loops):

| Role | publishes | subscribes |
|---|---|---|
| `display` (`?kraken=1`) | `tele` only | `state`, `cmd` |
| `config` (CAM Configuration Browser) | `state`, `cmd` | `state`, `tele` |
| `remote` (phone/desktop) | `state`, `cmd` | `state`, `tele` |

The display **never publishes state**. When it persists remote state locally (`persistRemote`), that write goes only to localStorage — which reaches the CAM config browser through `LocalStorageTransport`, so all three surfaces converge without any peer echoing state back onto the network.

### 6.2 `src/platform/geometry.ts`

```ts
export interface Geometry {
  width: number; height: number;
  shape: 'circle' | 'square';
  targetFps: number;
  dpr: number;                          // window.devicePixelRatio — UNVERIFIED on hardware, reported in tele
  source: 'nzxt' | 'sim' | 'url' | 'fallback';
  safeInsetPx: number;                  // practical text/UI inset
  inscribedSquarePx: number;            // guaranteed-visible square side

}

export function applyGeometryToDom(g: Geometry, render: RenderSettings): void;
export function watchGeometry(cb: (g: Geometry) => void): () => void;   // 2 s poll of window.nzxt.v1
```

- Fallback when `window.nzxt` is absent: `640 × 640`, `circle`, `targetFps = prefs.fallbackTargetFps` (default **30**, not 1 — an absent object tells us nothing about the slider, and defaulting to 1 would cripple a display whose injection merely arrived late). `source: 'fallback'` is surfaced in `?debug=1` and telemetry.
- `targetFps` is clamped to `[1, 60]`; `NaN`/missing → fallback. Unknown `shape` values → treated as `'square'` (safest: no mask, no inset loss) and logged.
- `watchGeometry` polls `window.nzxt.v1` every 2 s because it is **unverified** whether CAM mutates `targetFps` live when the user drags the slider. A change fires `renderer.geometry(g)` and re-evaluates the low-FPS banner.

Safe area, circle:
- `radiusPx = min(width, height) / 2`
- `inscribedSquarePx = min(width,height) / Math.SQRT2` → 452 px on 640. Content fully inside this is guaranteed visible; the corresponding inset (~93.7 px) is too aggressive for general layout.
- `safeInsetPx = round(min(width,height) * render.safeAreaPct)`, default `0.08` → **51 px on 640**, matching community practice (6–10 %). Configurable 0–0.2.
- Square shape → `safeInsetPx = round(min(w,h) · render.safeAreaPct)` — **19 px on the 240 px square panel** — and `inscribedSquarePx = min(w,h)`. The inset is not zero on a square: a rectangle has no cropped corners, but it still has bezel and a viewing angle, and the one number every module lays text out against must not change meaning with the shape.

`applyGeometryToDom` sets on `:root`: `--kh-w, --kh-h, --kh-r, --kh-safe, --kh-inscribed, --kh-target-fps, --kh-bg`, plus `<html data-shape="circle|square" data-kraken="1">`.

**The stage gets `border-radius:50%; overflow:hidden; background:#000` when the mask is on.** Two reasons: it prevents corner content bleeding into CAM's capture, and — more importantly — it forces the corners to flat black, which is cheap for the Elite's frame compressor. Given that achieved FPS is content-dependent (research), masking the ~21 % of the frame that is invisible anyway is a free FPS win.

Fit math: media fits the **circumscribed** square (`cover`) so there are no black gaps inside the circle; overlays/text respect `safeInsetPx`. `render.rotate` and `zoom` compose into a single `transform: rotate(Xdeg) scale(Z) translate(ox,oy)` on the media layer with `transform-origin: center`.

### 6.3 `src/platform/fpsGovernor.ts`

```ts
export interface FrameInfo { t: number; dt: number; frame: number;
                             targetFps: number; budgetMs: number; achievedFps: number }
export interface FrameClock {
  subscribe(cb: (f: FrameInfo) => void): () => void;
  pause(reason: string): void; resume(reason: string): void;
  stats(): { achievedFps: number; longFrames: number; lastTickAt: number; paused: boolean };
}
export function createFrameClock(getTargetFps: () => number): FrameClock;
```

- One global `requestAnimationFrame` loop for the whole page. Gate: `if (now - nextAt < 0) return; nextAt += interval;` with `nextAt = max(nextAt, now - interval)` to avoid death-spiral catch-up after a stall.
- `targetFps` is read **every tick** from `getTargetFps()` so a mid-session slider change takes effect immediately.
- `achievedFps` = EMA over a 2 s window. `longFrames` counts callbacks exceeding `budgetMs = 1000/targetFps`. Both flow into telemetry and `?debug=1`.
- Every subscriber callback is wrapped in try/catch; 3 consecutive throws → unsubscribe + report (see §2.3).
- `pause()` on `document.hidden` (saves the user's CPU when CAM isn't capturing) — but note the watchdog uses `setInterval`, not rAF, precisely so it keeps ticking while rAF is throttled.
- Sets the `inFrame` flag used by invariant I4.

**Low-FPS banner** (`LowFpsBanner.ts`). Shown when all hold:
`geometry.targetFps <= platform.lowFpsThreshold (5)` **and** the composed stack is not entirely static (`stackMotionLevel(look) !== 'static'`) **and** the base module does not draw its own advisory (`capabilities.ownsFpsAdvisory`, video only) **and** — round 12, F12-1 — **the slider has somewhere to go**: `maxTargetFpsForPanel(width, height, shape) === null || targetFps < that maximum`.

That last clause is the whole of a Kraken Z: CAM offers it exactly one frame rate, 1 FPS, which is also the threshold — so a stock Z wore a permanent card telling it to drag a slider that is already at maximum to maximum, and then a permanent badge. A panel at its ceiling is shown nothing. An **unrecognised** panel (`null`) still gets the advisory: a ceiling we cannot name is not a ceiling we can claim was reached. The same gate is inside the video module's own advisory (`modules/video/ui/FpsAdvisory.ts`, `maxTargetFps` option), because it is the surface the shell stands down for.

Content, laid out entirely inside `safeInsetPx`, high contrast, 26.9 px body type at 640: the frame rate as a title, then `camPaths.fpsAdvisoryBody(max, { leadIn: true })` — the ONE sentence, with the attached panel's ceiling in it (*"Drag … to maximum (40 FPS on this panel)."*) — then *"This notice disappears once a higher frame rate is set."* The shell must never re-assemble that sentence from `CAM_FRAME_RATE_LEAD`/`_TAIL` (F12-3): doing so dropped the per-panel number and left the paragraph starting on a lowercase verb.

**Round 13, M2 — `leadIn`.** Re-assembly was fixed; the lowercase verb was not. `fpsAdvisoryBody()` shipped only the mid-sentence form, because About and `CamSetupCard` end a longer sentence with it (*"Point CAM at this page, then drag …"*). The display card and the config home banner are whole paragraphs, and both began *"drag CAM → …"*. One function now serves both: `{ leadIn: true }` capitalises the verb and nothing else, from the derived `CAM_FRAME_RATE_LEAD_SENTENCE` — which is also what JSX surfaces that bold the path themselves pick up, so there is still one instruction.

**Round 13, F1 — "entirely inside `safeInsetPx`" was aspirational.** The card's type was `--kh-inscribed / 14`, with title 1.5em, body 0.95em and footer 0.8em on top of it, and the resulting box was **taller than the box it is centred in**: 405 px in 398 px of room on a 640 Elite, and 233 px in 202 px on a 240 Kraken — 12 px past the glass, with the footer sheared off. The video module's own card on the same panel fit exactly, because it sizes each paragraph off `--kh-inscribed` directly (`/13`, `/18`, `/22`). The shell card is sized the same way now — divisor **16**, putting the body at `inscribed / 16.8` — and below **300 px inscribed** the footer line is *dropped rather than shrunk*, the same rule and the same threshold as the video card's route footer (`FOOTER_MIN_INSCRIBED`). Measured on the built app: 640 Elite 322 px of card in 398 px of room (body 26.9 px, footer kept); 240 Kraken 146 px in 202 px (body 14.3 px, footer dropped); a 320 Z is silent under F12-1 anyway.

It shipped because every display spec ran at the config's default 640×640 viewport and asserted on **text**, so a card hanging off the disc read as passing. `boot-display.spec.ts` now sets the viewport per panel and asserts geometry — card height and width ≤ `panel − 2 × safeInset`, card bottom on the panel — at 240 and 640.

Shrinks to a badge after 20 s — `‹n› FPS ⚠`, the same string the video module's badge uses — and re-shows as a full card whenever a NEW `targetFps` is observed, until `targetFps > 5` is seen. Mirrored as a telemetry flag and as a persistent warning card in the config UI's SetupView — this single message is the highest-leverage piece of UX in the whole app, because a user who never touches the slider sees a 1 FPS slideshow and blames us.

### 6.5 `src/platform/watchdog.ts`

```ts
export function createWatchdog(o: {
  frameClock: FrameClock; monitoring: MonitoringSource; geometry: () => Geometry;
  isKraken: boolean; prefs: PlatformPrefs;
  onSoftReinit(reason: ReinitReason): void;      // re-arm nzxt, refresh state, renderer.reinit()
  onRemount(reason: ReinitReason): void;         // unmount + mount the module fresh
  onHardReload(reason: string): void;            // location.reload(), rate-limited
}): { start(): void; stop(): void; report(): WatchdogReport };
```

Driven by a **2 s `setInterval`** (deliberately not rAF — rAF is exactly what may have stalled). Detectors:
- `rafStall`: no frame callback for `> max(3000, 5 × frameIntervalMs)` while not paused.
- `monitoringStall`: `isKraken && everReceivedData && now - lastUpdateAt > 8000` → first re-arm the handler (CAM may have swapped `window.nzxt`), then escalate if still stale after another 8 s.
- `mediaStall`: module-reported via `ctx.telemetry({stalled:true})` (e.g. `<video>.currentTime` frozen for > 4 s while `!paused`).
- `geometryChange`: width/height/shape differ from the mounted values → `renderer.geometry()`, or remount if the module lacks that hook.

Recovery ladder, escalating, each step logged to a 64-entry ring buffer surfaced in `?debug=1` and telemetry:
1. **Soft re-init** — `rearmMonitoringHandler()`, `readGeometry()`, refresh state from localStorage, `renderer.reinit(reason)`.
2. **Remount** (if still stalled 10 s later) — `unmount()` + fresh `mount()`. New `<video>` / new iframe: this alone fixes most media-level freezes.
3. **Hard reload** (if still stalled 30 s later and `prefs.allowWatchdogReload`) — `location.reload()`. Safe under invariant I1 because the URL is unchanged, so it is not a navigation. **Rate-limited to 1 reload per 5 minutes** via `kraken-hub:watchdog:v1`; after 3 reloads in 30 minutes, stop reloading permanently for the session and render a static error card. A frozen error card is strictly better than a boot loop on someone's cooler.

Lifecycle handlers registered at boot: `visibilitychange`, `pageshow` (including `event.persisted` bfcache restores), `pagehide`, and Page Lifecycle `freeze`/`resume` where available. Every visible transition triggers the step-1 soft re-init path — this is the primary defense against the documented freeze-after-Windows-sleep failure mode.

## 7. Boot sequences and data flows

### 7.1 Display boot (`?kraken=1`)

Target: black pixels immediately, module visible within ~300 ms, zero blocking network beyond the module's own media.

1. Browser parses `index.html`; inline CSS paints `#000` (never a white flash on the LCD).
2. `main.tsx` reads `kraken=1` → `import('./boot/bootDisplay')`. The config chunk is never requested.
3. `bootDisplay()`:
   a. `installSimulator()` if `sim=1`/DEV **and** no real `window.nzxt`.
   b. `geometry = readGeometry()` (possibly `source:'fallback'`) → `applyGeometryToDom()`. Start `watchGeometry` (2 s poll).
   c. Kick `whenNzxt(2000)` **without awaiting** — on resolve, re-read geometry, re-apply DOM, arm the monitoring handler, re-evaluate the low-FPS banner.
   d. `const persisted = readState()` (parse → migrate → validate). `const url = parseUrlParams()`. `const resolved = resolveState({defaults, url, persisted, remote:{}})`. The same parsed `url` patch is then installed as a non-persistent store overlay by `mountDisplayApp` (f), which is what makes a URL parameter win unconditionally (§4.1) — there is no `pin` flag.
   e. Create `monitoring`, `frameClock`, `mediaStore`, `blobUrls`.
   f. `mountDisplayApp(#root, runtime)` — stage > [compositor root, splash | error card, LowFpsBanner?, DebugOverlay?, DiagOverlay?]. Total tree ≈ 12 nodes, written directly; no framework is downloaded on this path (§2.1).
   g. `ModuleHost` resolves `activeModuleId` → `getModule(id)` (falls back to `DEFAULT_MODULE_ID` if unknown) → `await mod.loadDisplay()` → `createRenderer()` → `mount(host, ctx, cfg)`. A minimal splash (module name) appears only if the dynamic import exceeds 200 ms.
   h. Start `watchState()` → on change: if `activeModuleId` changed → unmount + mount; else compute the changed dot-path set and call `renderer.update(cfg, {changed, origin:'local'})`.
   i. If `sync.enabled && sync.roomCode` → `new SyncService({role:'display'}).start()` in the background. **Never blocks rendering.** Subscribes `state` + `cmd`; publishes `tele` at 1 Hz.
   j. `watchdog.start()`; register `visibilitychange` / `pageshow` / `pagehide` / `freeze` / `resume`.
   k. Start the resume writer: every 5 s and on `pagehide`, write `kraken-hub:resume:v1` from `renderer.timeline()`.
   l. `navigator.storage.persisted()` → if false, attempt `persist()` (likely denied without a gesture; log the result for Diagnostics).
   m. Run `capabilities.probe()` once, attach to telemetry.

### 7.2 Config boot (no `?kraken=1`)

1. `main.tsx` → `import('./boot/bootConfig')` → React + `src/ui` + all lazy panels available.
2. `readState()` + `migrate()`. If `migrate` reported `future-schema`, render a persistent banner: "These settings were saved by a newer version of kraken-hub. Update, or continue with defaults (your saved settings are preserved)."
3. `router.ts`: parse `location.hash` → view; listen on `hashchange`. Hash-only, never `pushState` — GitHub Pages has no rewrites, and keeping the rule uniform across both pages removes a whole class of mistakes.
4. Detect CAM Configuration Browser: `peekNzxt() !== null || /Electron/i.test(navigator.userAgent)`. Determines `role = 'config' | 'remote'` and drives the "Connected to CAM" chip.
5. Views:
   - `#/` **SetupView** — device/CAM detection, one-click install buttons + copyable canonical URL, the **Frame Rate slider** instructions with a screenshot (docs 02), storage-persist request button, module picker.
   - `#/module/<id>` **ModuleSettingsView** — lazily renders `mod.ConfigPanel`.
   - `#/remote` **RemoteView** — create/join a room, QR code + shareable link (`…/#/control?room=XXXXXXXX`), transport status, optional passphrase.
   - `#/control` **ControlView** — the phone controller (transport bar, scrubber, A-B loop dual slider, fit/zoom/rotate, module switcher, `identify` button, live telemetry).
   - `#/preview` **PreviewView** — §6.6.
   - `#/diagnostics` **DiagnosticsView** — capabilities report, storage-event vs poll counters, validation/param notes, watchdog log (via telemetry), "Copy report".
   - `#/about`.
6. `SyncService({role})` starts if a room is configured.
7. Every edit → `store.commit()` → one `setItem` → `storage` event to the display **and** `sync.publishState()` (debounced 200 ms).

### 7.3 Flow A — user changes the video URL in CAM's Configuration Browser

1. `#/module/video`, paste URL → `providers/validate.ts`: `http://` → offer https upgrade or reject; `.mkv` → hard reject with "Chromium cannot play Matroska — convert to MP4/WebM"; `cdn.discordapp.com` → warn "this link expires in ~24 h"; otherwise detect provider → `SourceRef`.
2. Apply → `commit(s => ({...s, modules:{...s.modules, video:{v:VIDEO_CFG_V, cfg:{...cfg, source}}}, playback:{...s.playback!, posSec:0, posAtTs:Date.now(), paused:false}}))`.
3. One `setItem('kraken-hub:state:v1', json)`; `rev+1`, `writerId = configClientId`, `writerRole='config'`.
4. Kraken Browser: `storage` event (key match) → `watchState.refresh('event')` → parse → migrate → validate → `resolveState` → diff against the previously resolved state.
5. Diff = `['modules.video.cfg.source', 'playback.posSec']`, `activeModuleId` unchanged → `renderer.update(cfg, {changed, origin:'local'})`.
6. `VideoDisplay` compares `source.key`; different → abort in-flight loads via `ctx.signal`, tear down the current engine (iframe or `<video>`, revoking blob URLs), select the engine via the provider registry, mount the new one, reset loop state, `ctx.telemetry({engine, status:'loading'})`.
7. If the `storage` event does not fire (Electron quirk), the 1 s poll catches it — worst case 1 s latency, and the delivery mechanism is counted for Diagnostics.
8. The config UI shows "Applied" only after it observes a `tele` envelope (over `LocalStorageTransport`) whose `moduleId`/`engine` reflect the new source; after 3 s with no echo it shows "waiting for the display…". This doubles as a live health check of the channel that everything else depends on.
9. In parallel, ConfigApp publishes the full snapshot retained over MQTT so any connected phone reflects the change.

### 7.4 Flow B — user drags the A-B loop sliders on the phone remote

1. `ControlView` dual-thumb slider bound to `playback.loop.startSec/endSec`. `onInput` can fire at 60 Hz.
2. Local optimistic UI update immediately (no round-trip lag on the phone).
3. `sync.publishState()` — debounced 150 ms, hard-throttled to 5 Hz. Rationale: ntfy's publish rate limit is undocumented, and the display must not re-seek per pixel of drag.
4. Additionally, `sync.sendCmd('previewSeek', {sec})` at 5 Hz for scrub preview — **transient, never retained**, so a display reload never replays a stale scrub.
5. Envelope sealed (AES-GCM, AAD `topicId|state`) → `PUBLISH kh/v1/<topicId>/state`, `retain: true`, QoS 0.
6. Display's `MqttTransport` receives → `SyncService` decrypts → dedup `(src,seq)` → `rev > lastAppliedRev` → `onState`.
7. Display merges into the **remote layer**, recomputes the resolved state, calls `renderer.update(cfg, {changed:['playback.loop'], origin:'remote'})` and `renderer.applyTimeline(playback, 'remote')`.
8. `VideoDisplay` updates the loop bounds **without seeking** unless `currentTime` now falls outside `[start, end]`. On `pointerup` the phone sends one final un-throttled state plus, if `loop.enabled`, `cmd:seekTo(start)`.
9. `persistRemote` (default true) → display commits the remote state to localStorage, throttled ≥ 2 s, coalesced, `writerRole='display'`. The `storage` event reaches the CAM config browser, whose form updates — all three surfaces converge, with no state ever echoed back onto the network by the display.
10. Display publishes `tele` at 1 Hz with the actual `posSec`. The phone's scrubber snaps to telemetry only when `Date.now() > draggingUntil` (set to `lastInput + 800 ms`), so the thumb never fights the user's finger.

### 7.5 Flow C — display recovers after PC sleep

**C1 — page survived, frozen.** `pageshow` / `visibilitychange→visible` / Page-Lifecycle `resume` fires → watchdog step 1: `rearmMonitoringHandler()` (CAM may have re-injected `window.nzxt`), `readGeometry()` (the user may have changed the FPS slider while we were out), `watchState.refresh()`, `frameClock.resume()`, `renderer.reinit('resume')`. `VideoDisplay.reinit` for a `<video>`: if `readyState === 0` call `load()` then seek + `play()`, else just `play()` and re-seek; for the YouTube square iframe: `playVideo()`, and if `getPlayerState()` is still UNSTARTED/CUED after 3 s, recreate the iframe outright. If the module remains stalled, the watchdog escalates to remount, then to a rate-limited reload.

**C2 — CAM reloaded the page, or the watchdog forced a reload.** Full §7.1 boot runs. Position-recovery ladder:

1. `kraken-hub:state:v1` → `playback.posSec` + `posAtTs`.
2. `kraken-hub:resume:v1` (written by the display every 5 s and on `pagehide`) — **preferred when its `posAtTs` is newer and its `srcKey` matches** the resolved source; it is up to 5 s stale versus potentially hours for the state key.
3. Compute the effective start:
   ```
   ageSec = (Date.now() - posAtTs) / 1000
   if (paused || ageSec > 300)  start = posSec                      // cold start: use the SAMPLED value
   else                          start = posSec + min(ageSec, 30)    // brief gap: extrapolate, clamped
   if (loop.enabled) start = clamp(start, loop.startSec, loop.endSec ?? duration)
   if (duration && start >= duration - 0.5) start = loop.startSec ?? 0
   ```
   The clamps matter: a PC asleep for eight hours would otherwise seek eight hours into a three-minute video. **Never extrapolate more than 30 s of elapsed wall-clock**, and after a 5-minute gap do not extrapolate at all.
4. If MQTT is enabled, the retained snapshot arrives ~1–3 s later. Applied only if `rev > local rev`, then re-anchored through the same clamped math. If the phone was offline for the whole sleep, the retained snapshot is stale — the `ageSec > 300` rule is exactly what prevents it from producing a nonsense seek.
5. If the module's media came from IndexedDB and the row is gone (eviction), `ModuleErrorCard` shows "media missing — reconnect in settings" rather than a black screen, and telemetry carries the missing `mediaId`.

## 8. Risks, unknowns, and graceful degradation

| Failure | Detection | Degradation |
|---|---|---|
| `window.nzxt` never injected | `whenNzxt` → null; re-checked at 10 s and on every `pageshow` | Geometry falls back to 640×640 circle, `targetFps = prefs.fallbackTargetFps` (**30**, not 1). App fully functional; `source:'fallback'` chip in `?debug=1` and telemetry. |
| `window.nzxt` reassigned by a contributor (the official docs' own footgun) | DEV `defineProperty` tripwire logs a stack; ESLint restricts the property outside `nzxt.ts` | Caught in development, never ships. |
| `storage` event unreliable in the CAM webview | 1 s poll always running; `{viaEvent, viaPoll}` counters | ≤ 1 s latency instead of failure. Counters make the real behavior empirically visible to the community. |
| `localStorage` full / disabled (origin shared with the user's other github.io repos!) | `QuotaExceededError` on `setItem` | Store degrades to in-memory + URL params; config UI shows the quota number, lists `kraken-hub:*` key sizes, and explains the shared-origin cause. Blobs are unaffected (separate IndexedDB quota). |
| State JSON > 256 KB | pre-write assert | Write rejected with a specific error rather than a silent truncation. Blobs are structurally excluded (I6). |
| MQTT broker down / WSS on :8084 firewalled | 8 s connect timeout; 3 failures in 60 s | Auto-failover to ntfy; remote shows "fallback transport". Background mqtt re-probe every 5 min with a 10 s dual-subscribe handover. |
| Both network transports down | `SyncStatus.network = 'offline'` | Display keeps playing from persisted state (it never depends on sync to function). Remote page: "offline — use the CAM configuration browser." |
| ntfy rate-limits (429, undocumented) | HTTP status | Backoff + coalesce; drop non-critical `cmd`s; enter "state-only every 4 min" mode with a visible notice. |
| Retained message expiry (undocumented on EMQX) | none directly | 5 min republish by the last writer + `cmd:requestState` on every peer connect. |
| ntfy replay delivers a stale `cmd` | `Date.now() - env.ts > 15 s` | Dropped. This is why `cmd` is a separate channel from `state` and is never retained. |
| Wrong room code | 10 decrypt failures in 30 s | "No messages could be decrypted — check the room code." Never silently half-works. |
| Two controllers editing simultaneously | Lamport `rev` + `(ts, src)` tiebreak | Last-writer-wins on the whole document. Documented as intentional (not CRDT): the state is small and human-driven. |
| Feedback loop between the three surfaces | role matrix (§5.5) + `writerId` echo suppression + `rev` monotonicity | Structurally impossible: the display never publishes state. |
| IndexedDB evicted (`persist()` denied) | `getMedia(id)` miss | "Media missing — re-upload" card; config offers re-link by name+bytes+sha256. State retains the `mediaId`. |
| CAM webview lacks a codec (HEVC needs GPU decode; AV1 uncertain) | `capabilities.probe()` at boot | Config UI warns at input time; player falls back or shows an actionable error instead of a black frame. |
| Module throws in `mount`/`frame`/`monitoring` | try/catch + 3-strike unsubscribe + the shell's own `try`/`catch` (§2.1) | `ModuleErrorCard` sized for 640 px with the error text; telemetry carries the stack. Other subsystems keep running. |
| Watchdog reload loop | `kraken-hub:watchdog:v1` counters (survive the reload) | 1 reload / 5 min; after 3 in 30 min, stop reloading permanently for the session and show a static error card. |
| A UI framework returns to the display path | `displayCriticalPath` budget (35 KB gz) + the `displayNoFramework` graph walk + `longFrames` telemetry | W9 removed the framework outright rather than shrinking it — the `preact/compat` alias this row used to reserve is moot. A reintroduced component fails `npm run size` on the built graph, not in review. |
| Fork on a different `<user>.github.io` | — | All keys namespaced `kraken-hub:`; `base: './'`; hostname-dependent embed params read from `location.hostname`; no hardcoded origin anywhere. |
| GitHub Pages trailing-slash 301 on the CAM URL | — | Docs, one-click buttons, and the "Copy URL" button all emit the trailing slash (`new URL('./', location.href).href`). |
| `?v=` "does nothing" after the user saves settings (precedence surprise) | — | **Not a surprise as shipped, and `?pin=1` is gone (round 13, M1).** A URL parameter is applied as an overlay ON TOP of the resolved document (`src/app/display/mount.ts`), so it already wins over persisted state on every load and there is nothing to promote — `flags.pin` was written by the parser and read by no file in the tree, which is a worse failure than the one it was meant to mitigate: a reader told to add `?pin=1` would get an "unknown parameter" note and conclude the override itself had not worked. The mitigation that does exist is the readout: the config UI lists every URL param it saw, and every one it ignored with the reason. |

**Unknowns, each wired to a Diagnostics readout so the community fills them in:** `devicePixelRatio` in the Kraken Browser (the YouTube square-iframe quality math assumes 1); whether CAM applies its own circular mask; the exact Chromium/Electron version and thus WebCodecs/AV1/HEVC availability; whether webview audio reaches the speakers (why `platform.audioOptIn` defaults false and the display forces `muted`); whether CAM mutates `targetFps` live (why `watchGeometry` polls every 2 s); CAM's reload cadence and whether changing CAM settings reloads the page; localStorage/IndexedDB persistence across CAM restarts and updates (determines whether the room code survives on the display side); Kraken Plus (2025) reported geometry; and achieved FPS for a video frame vs. a flat frame at max slider. `#/diagnostics` → **"Copy report"** emits a markdown block ready to paste into a GitHub issue; `docs/92-troubleshooting.md` asks users to do exactly that.

**Testing plan (brief):** Vitest + jsdom for `state/*` (migration fixtures `state-v<N>.json`, precedence matrix incl. the URL overlay, validator fuzz), `sync/*` (roomCode round-trip, crypto seal/open + AAD-mismatch rejection, envelope dedup/staleness, failover state machine with fake transports), `platform/fpsGovernor` (fake timers: gating, drift, spiral-of-death guard), `platform/watchdog` (fake timers: each escalation step and the reload rate limiter); `fake-indexeddb` for `media/*`; the §2.4 registry conformance suite over every module; Playwright for both boot paths, a scripted two-context localStorage handoff (config write → display apply), and a `?kraken=1&sim=1` visual snapshot at 640/320/240.
