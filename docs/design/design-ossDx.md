## 0. Decisions made here (no options left open)

| Question | Decision | Rationale |
|---|---|---|
| Package manager | **npm** (lockfile `package-lock.json`) | Node 22 ships npm 10; `corepack` is absent on the dev machine and the local `pnpm` is 0.34.6 (ancient/broken). One fewer prerequisite in CONTRIBUTING, native `actions/setup-node` cache, zero version-pinning ceremony. Single package, no monorepo, so pnpm's wins don't apply. |
| Versioning | **Manual semver + Keep a Changelog**, no changesets | Nothing is published to npm; the deploy is continuous. Changesets adds a bot + PR-per-release flow for zero benefit. `CHANGELOG.md` edited in-PR (enforced by PR template checkbox), `npm version` + tag on release. |
| Docs site generator | **None.** Plain markdown in `docs/`, rendered by GitHub | The Pages root is the *app*. A docs site would fight `base: './'`, add a second build, and split the deploy. GitHub's markdown rendering is the target. |
| Pre-commit hooks | **Opt-in only**, `core.hooksPath` + `.githooks/`, never auto-installed | No `prepare: husky` surprise on `npm ci`. CI is the enforcement point; hooks are a convenience. |
| E2E runner | **Playwright**, Chromium only | Target is a Chromium webview. Firefox/WebKit runs would be misleading and triple CI time. |
| MQTT in CI | **Fake transport always; live broker opt-in, weekly, non-blocking** | Never hammer `broker.emqx.io` from PR CI. |
| Runtime deps from CDN | **Banned.** `mqtt` is a bundled dependency | Enables strict CSP (`script-src 'self'`), reproducible builds, offline demo mode, no third-party supply chain on the display path. |
| Docs licensing of bundled demo clip | **Repo-authored clip, MIT with the repo** | Avoids CC-BY attribution obligations and is deliberately low-entropy (best case for the Elite's frame compressor). |

**SECURITY.md** —
- Supported versions: only the currently deployed `main` (continuous deploy; there are no back-ported releases).
- Reporting: GitHub Private Vulnerability Reporting (must be enabled in repo settings), 90-day coordinated disclosure, target 72 h acknowledgement.
- **Threat model** (the section that matters):
  - Public MQTT brokers are world-readable and world-writable. The room code is a *capability*, not a username. A leaked code lets anyone change what is displayed and read your media URLs.
  - Mitigation: topic is `SHA-256(roomCode)`-derived so the code never transits; payloads are AES-GCM with an HKDF-derived key from the same code. A broker operator sees ciphertext of unknown length only.
  - What we never transmit: local file bytes (IndexedDB only, same machine), and CAM monitoring data (stats module telemetry to the remote is **off by default**).
  - XSS surface is user-pasted URLs. All external input passes a zod schema; `http://` is upgraded-or-rejected; `javascript:`/`data:` (non-image) rejected; no `dangerouslySetInnerHTML`; no `eval`; no CDN scripts.
  - CSP delivered as a `<meta http-equiv>` in `index.html`: `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob: https:; media-src 'self' blob: https:; connect-src 'self' https: wss: http://127.0.0.1:* http://localhost:*; frame-src https:; object-src 'none'; base-uri 'none'`. Requires `build.modulePreload.polyfill: false` in Vite so no inline script is emitted.
  - Resolver companion: binds loopback only, Origin-allowlisted, bearer-token paired. `docs/resolver-protocol.md` is normative; a companion that skips these is out of spec.
  - Out of scope: a compromised host machine; CAM itself; the security of third-party embed providers.

**`.github/dependabot.yml`** — two ecosystems (`npm`, `github-actions`), weekly, `groups: { minor-and-patch: { update-types: [minor, patch] } }`, majors individually, `open-pull-requests-limit: 5`.

### 3.3 MQTT integration without hammering the public broker

1. **Abstraction.** `src/sync/transport.ts` defines
   `interface SyncTransport { connect(): Promise<void>; publish(ch: Channel, payload: Uint8Array, opts: { retain: boolean }): Promise<void>; subscribe(ch: Channel, cb: (p: Uint8Array, retained: boolean) => void): Unsubscribe; close(): Promise<void>; readonly status: TransportStatus }`.
2. **`FakeTransport`** (`src/sync/fake.ts`) — in-memory retained map + subscriber set for unit tests; `BroadcastChannel`-backed variant for e2e so two Playwright pages can talk. Ships in the production bundle only behind `?transport=fake` (tree-shaken out of the default path via a dynamic import guard).
3. **Contract suite** runs against `FakeTransport` on every CI run. Real transports are never contacted in PR CI. `vitest.config.ts` sets `test.env.KRAKEN_HUB_LIVE = '0'` and the live specs are `describe.skipIf(!process.env.KRAKEN_HUB_LIVE)`.
4. **Live smoke** — `npm run test:live`, guarded by `KRAKEN_HUB_LIVE=1`. Constraints baked into the test: a fresh random topic `kraken-hub/ci/<uuid>` per run; ≤ 10 messages total; a mandatory **await-CONNACK → publish → await-puback/flush → 500 ms settle → close** sequence (the empirically observed retained-message loss race); the retained message is **cleared** at teardown by publishing a zero-length retained payload; a hard 45 s suite timeout.
5. **Workflow** `live-smoke.yml`: `on: workflow_dispatch` + `schedule: '0 6 * * 1'` (weekly), `concurrency: { group: live-smoke, cancel-in-progress: false }`, `continue-on-error: true`, and a final step that opens-or-updates a single tracking issue titled *"Live transport smoke failing"* so a broker outage never reds the tree or spams issues. Never runs on `pull_request`.
6. **Local option** — `docs`-documented `docker run -p 1883:1883 -p 8080:8080 eclipse-mosquitto` with a `mosquitto.conf` snippet, for contributors who want a real broker without touching a public one.

### 3.4 On-device verification — `docs/hardware-checklist.md` + `#/diag` + `?diag=1`

**Two surfaces, one report.**
- `?kraken=1&diag=1` → the **LCD overlay**: huge high-contrast type, auto-paginating every 8 s (`&page=N` pins a page), designed to be photographed. Page 1 identity/geometry, page 2 capabilities/codecs, page 3 timing/FPS, page 4 storage/liveness.
- The display page **writes** its collected `DiagReport` to `localStorage['kraken-hub@<path>:diag:report']` every 5 s. **Splitting discipline (the display path is the budget that matters).** `src/main.tsx` does mode detection and then statically imports *nothing* mode-specific — it `await import()`s exactly one of `./app/display/mount`, `./app/config/mount`, `./app/remote/mount`. Modules and providers are `import()`ed from their registries, so a display running the Clock module downloads: `index.html` + entry + `vendor-react` + `display-shell` + `module-clock`, and never touches `module-video`, any provider chunk, `mqtt`, or the entire config UI. `mqtt` is imported only when a room code exists **and** the transport is `mqtt`. `hls.js`/`dash.js` are imported only when a URL of that kind is actually selected.

### 4.5 Versioning and release

- `CHANGELOG.md` follows Keep a Changelog with an `## [Unreleased]` section; PRs add a line there (PR-template checkbox; a CI step warns — does not fail — when a PR touches `src/**` without touching `CHANGELOG.md`).
- Release: maintainer runs `npm version minor` → commit + tag `vX.Y.Z` → push tag → `release.yml` builds, runs `scripts/extract-changelog.mjs vX.Y.Z`, and creates a GitHub Release with that body. **Deployment is decoupled** — `main` deploys continuously; tags are documentation of state, not a gate.
- Version surfacing: config UI footer renders `kraken-hub vX.Y.Z · <sha> · built <date>` with the sha linked to the commit; the diag overlay prints the same; `README` badge tracks the latest release.
- Semver meaning for a hosted app, documented in CONTRIBUTING: **major** = a state-schema migration that a downgrade cannot read, or removal of a module/provider/URL param; **minor** = a new module, provider, or setting; **patch** = fixes and docs.

## 7. Open risks this plan deliberately absorbs

- **Chromium version in the CAM webview** was unknown, so `build.target: chrome108` was a guess. H18 is now confirmed on CAM 4.76.5 — Electron 32.1.0 / Chromium 128 (see the hardware-checklist known results) — so the target is conservative rather than wrong, and stays until more than one CAM build has been seen. The original reasoning, still live for any future report: if reports show a newer engine, raise the target in a patch release and note it in CHANGELOG. If they show an *older* engine, `chrome108` may itself be too aggressive — the diag `userAgent` readout is the first thing to check when a user reports a blank display.
- **The square-iframe geometry engine is corroborated but not instrumented.** M1's acceptance criteria are simulator-based; the on-hardware confirmation is H05 + H11 in M4. The provider interface is designed so a fallback 16:9 oversized iframe is a config flag, not a rewrite.
- **Public brokers are best-effort.** The transport abstraction, the fallback, the user-overridable endpoints, and the non-blocking live smoke job are all consequences of that; nothing in PR CI depends on a third party being up.
- **`storage` event reliability in an Electron webview is unproven.** The 1 s poll fallback is unconditional, and `storage-sync.spec.ts` tests the fallback path explicitly rather than assuming the event works.
